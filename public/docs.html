Qpay Developer Docs

Complete reference for Qpay — the payroll & token swap platform on QMS Testnet. Covers wallet setup, payroll management, token swaps via QWAP, contract addresses, and the full API surface.

Introduction

Qpay is a decentralised finance (DeFi) application built on the QMS Blockchain that provides two core services:

  • Payroll — create and pay employee salary entries using on-chain stablecoin transfers (USDT or USDC) directly from your wallet to the employee's wallet address. No intermediary, no custodian.
  • Token Swap — exchange tokens on QMS Testnet via the QWAP decentralised exchange router (Uniswap V2-compatible). Real on-chain execution with live quotes, configurable slippage, and swap deadline.
⚠

Testnet only. Qpay v1.0 runs exclusively on QMS Testnet (Chain ID 19480). All tokens, transactions, and balances are for testing purposes. Do not use real funds.

Payroll — Overview

The Payroll module lets you create salary entries and execute on-chain stablecoin transfers to employee wallet addresses.

How it works

Each payroll entry is stored permanently in the QpayPayroll smart contract on QMS Testnet. When you click Pay, Qpay calls payEmployee(payrollId) on the contract — the contract pulls the token amount from your wallet (via ERC-20 allowance) and sends it directly to the employee's wallet. The contract enforces the start date: if block.timestamp < startDate, the call reverts with PayrollNotDueYet.

ℹ

Qpay does not escrow funds. The transfer is immediate and irreversible once confirmed on-chain. Always verify the employee's wallet address before paying.

Create Payroll

Navigate to Payroll → New Payroll (or tap Payroll in the bottom navigation, then the + button).

Fields

FieldTypeDescription
Employee NameTextDisplay name for the payroll record.
Wallet Address0x… addressThe recipient's EVM wallet address. Must be a valid checksummed address.
Salary AmountNumberAmount in the selected stablecoin (USDT or USDC). Uses 6 decimal precision.
TokenUSDT / USDCThe stablecoin to pay with. Cannot be changed after creation.
Start DateDateThe date the payroll becomes payable. The smart contract enforces this — payEmployee() reverts with PayrollNotDueYet if called before this date. The Pay button in the UI is also locked until the date arrives.

Validation

  • Wallet address must match /^0x[0-9a-fA-F]{40}$/
  • Amount must be greater than 0
  • Your wallet must be connected and on QMS Testnet
  • You must have sufficient stablecoin balance to pay

Pay Employee

On the Payroll list, each pending entry shows its due status. When the start date has arrived, use Pay All (batch) or pay individually.

Slippage & Deadline

Click the Auto slippage button (top-right of the swap card) to open settings.

Slippage Tolerance

Controls how much the output can deviate from the quoted amount before the transaction reverts.

ModeValueDescription
Auto2.5%Recommended for most swaps. Set automatically.
Manual0.01% – 50%Toggle Auto off and enter a custom value.
⚠

Setting slippage above 5% risks front-running. A warning is shown when you enter a high value.

Swap Deadline

The transaction will revert if not mined within this many minutes. Default: 5 minutes. Range: 1–60 minutes.

Formula: deadline = block.timestamp + (minutes × 60)

amountOutMin Calculation

// rawOut = getAmountsOut result (bigint)
// slipBps = slippage% × 100  (e.g. 2.5% → 250)
amountOutMin = rawOut - (rawOut × slipBps / 10000)

QpaySwap

0xeDDf43468577A03B89496A8869277Dd62791cf43
Network: QMS Testnet (Chain ID 19480) · Deployer: 0x4389006Dd061d13129a894b9E03a04EaE9B377b9 · Deployed: 2026-10-29 · View on Explorer ↗

The QpaySwap contract stores swap history permanently on-chain per wallet. After each QWAP swap is confirmed, the frontend calls recordSwap(wallet, txHash, tokenIn, tokenOut, amountIn, amountOut). History is readable via getSwapHistory(address) — no scanning, no localStorage. Ring buffer of 500 entries per wallet. Requires msg.sender == wallet for authenticity.

The Create2Factory is a permissionless deployment helper contract. Any caller can deploy arbitrary bytecode to a deterministic address derived from a salt and bytecode hash. It wraps OpenZeppelin's Create2.deploy.

Interface

// Deploy bytecode at a deterministic CREATE2 address

    bytes32 salt,
    bytes memory bytecode
) external payable returns (address deployed);

// Predict the address before deploying
function computeAddress(
    bytes32 salt,
    bytes32 bytecodeHash
) external view returns (address predicted);

FAQ

Why does my swap show "No liquidity for this pair"?

The QWAP pool for that pair may have no liquidity on testnet. Try a different pair or check the QWAP pools page.

Why does the Swap button stay disabled?

The button is disabled when: wallet is not connected, wrong network, amount is 0, no quote is available, or your balance is insufficient. Check each condition in order.

Why does the approval keep spinning?

Make sure the approval transaction is actually confirmed on-chain. If it failed, try again. If the spinner keeps going after a confirmed approval, try refreshing the page.

Is payroll data stored on-chain?

Yes. All payroll entries (employee name, wallet, amount, start date, status) are stored permanently in the QpayPayroll smart contract on QMS Testnet. Data is linked to your employer wallet address — connect the same wallet from any browser or device and your payrolls will be there.

Can I use Qpay on mainnet?

Qpay v1.2 is testnet-only. A mainnet deployment requires independent security review and production configuration.

What is the WQMS route?

WQMS (Wrapped QMS) is the hub token in the QWAP DEX. All pairs route through WQMS. So a USDT → USDC swap becomes USDT → WQMS → USDC on-chain. Qpay builds this path automatically.

Is swap history stored on-chain?

Yes. After each swap is confirmed, Qpay automatically calls recordSwap() on the QpaySwap contract. Your swap history is stored permanently on-chain and is accessible from any device or browser as long as you connect the same wallet. No localStorage is used.

My transaction reverted — what happened?

Common causes: slippage too low (price moved), deadline expired, insufficient gas (QMS), or the pool has insufficient liquidity. Increase slippage or retry.
